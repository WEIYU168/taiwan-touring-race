# 實景路線賽車遊戲

這個技能附帶一套已完成的遊戲引擎（`assets/template/`）：單一 HTML、純 WebGL2、沒有任何外部套件或素材，地形、植被、建物、車輛、音效都在執行時由程式生成。內建三條路線（139 縣道、墾丁台26、大鵬灣）、8 車對戰、線上多人、觸控操作、碰撞毀損、修復愛心與路上事件。

**做新景點＝在這個引擎裡加一條路線，不要重寫引擎。** 大部分工作是：查證實景 → 把查到的資料填進一筆路線設定 → 檢查 → 實跑 → 看截圖修正。

## 0. 準備專案

- 使用者已有專案（有 `src/js/14_routes.js`、`build.js`）：直接在那個專案裡工作。
- 沒有：把 `assets/template/` 整個複製成新的專案資料夾，之後都在新資料夾裡改。
- 先讀專案根目錄的 `AGENTS.md`（檔案分工、慣例、除錯介面）。只讀要改的檔案，不要整個專案讀一遍。

工具都是免費的：Node.js 16 以上；測試另需 Playwright（`npm i -D playwright && npx playwright install chromium`）。

## 1. 查證實景（先查再做）

用網路搜尋整理以下資料，**每項記下來源**，最後回報給使用者：

1. 起點、終點、實際長度（公里）、行經鄉鎮。
2. 沿途地標的**順序**與大概里程（廟宇、燈塔、橋、山峰、老街、觀景台……）。
3. 每一段的地景：山稜／海岸／平原／湖泊／城鎮；左右哪一側是海、山、田。
4. 植被與土地利用：森林種類、果園、茶園、檳榔、稻田、魚塭、沙灘、草原。
5. 海拔變化（起點、最高點、終點）。
6. 特殊天候或特色（常起霧、強風、落山風）。
7. 重要地標的外形（高度、形狀、顏色、材質），之後建模用。

查不到的（例如逐彎的 GPS 形狀）就用「依走向編排」，並在路線的 `note` 和回報中寫明。

## 2. 決定規格

- 遊戲賽段長度 7–12 km。實際路線較長就濃縮（例如 35 km → 12 km），保留地標順序與整體走向。
- 分成 4–8 個段落（`sections`），每段對應一種地景，HUD 會顯示段名。
- 選地形類型：`mountain`（山路）、`coast`（右側臨海）、`plain`（平原）。湖泊環線請參考範本裡的 `dapeng` 路線。

## 3. 產生路線骨架

```
node <技能資料夾>/scripts/new-route.js <專案> --key sunmoon --title "日月潭 環湖" --shield "台21" --type mountain --km 33 --len 9000
```

這會在 `src/js/14_routes.js` 加一筆可直接執行的骨架，並自動加進選單（`src/index.html`）與伺服器白名單（`server.js`）。骨架先建置跑一次確認能動，再開始改。

## 4. 依實景填寫路線

完整欄位說明見 `references/route-authoring.md`，先讀它再改。重點：

- `pieces`：`[長度 m, 轉角°]`，正＝左轉。依實際走向排列直線與彎道；**彎道半徑（長度 ÷ 弧度）至少 35 m**，賽道兩段之間至少相隔 80 m。
- `sections`：段名、副標、對應的實際里程 `k0`–`k1`。
- `elev`／`realAlt`：遊戲路面高度、實際海拔。
- `zones`：每段的土地利用比例 `w`（12 個數，順序見參考文件）、樹種 `mix`、行道樹 `row`。
- `zkeys`：每段路兩側地形（台地寬度、上下邊坡、起伏）。
- `plan()`：放地標；現成的地標類型與自製新地標的方法見 `references/landmarks.md`。
- `signs()`：觀光指示牌；要新文字就照參考文件新增一層貼圖。
- 選用：`fog: [s0, s1]` 起霧段、`bridge(s)` 橋段、`streets` 街屋段、`junctions` 路口。

修復愛心、防撞緩衝車、油罐車漏油、彎道警告標誌都會自動放置，不用設定。

## 5. 檢查與實跑（每次修改後都要做）

```
node <技能資料夾>/scripts/check-route.js <專案> <key>      # 欄位、長度、彎道半徑、分段覆蓋、賽道自我交叉
node build.js                                              # 在專案資料夾執行，產生 public/index.html
node <技能資料夾>/scripts/headless-check.mjs <專案> <key>   # 自動駕駛跑完全程、8 車對戰、各段截圖
```

- `check-route.js` 有 ✗ 就先修，不要建置。
- `headless-check.mjs` 必須顯示「自動駕駛完成全程」與「對手完賽 7／7」。
- **逐張看截圖**，對照第 1 步的資料：海、山在對的一側嗎？植被、建物、地標對嗎？不對就回第 4 步修改。
- 常見問題與修法見 `references/testing.md`。

## 6. 交付

- 單機：`public/index.html` 用瀏覽器直接開即可玩。
- 線上對戰：`node server.js`，再開它印出的網址。
- 回報給使用者時要寫清楚：
  - 新路線的內容與玩法。
  - 依據的資料來源。
  - 哪些部分是編排而非實測（彎道形狀、里程對應）。
  - 哪些沒驗證（真機幀率、真機手感）。
  - 已知粗糙處。

## 規則

- 不加 npm 套件、不用外部圖片／模型／字型檔（Google Fonts 連結除外），不用任何付費服務。
- `src/js/*.js` 依檔名順序串成同一個作用域：**不要用 import/export**；新檔用數字前綴，`99_main.js` 必須最後。
- 不要改 `13_game.js` 的物理或 `08_render.js` 的繪製管線，除非使用者明確要求；新路線只需要改 `14_routes.js`（加上需要時的 `11_props.js` 地標、`05_textures.js` 貼圖）。
- 介面文字用繁體中文。
- 座標：公尺；+X 東、+Z 南、+Y 上；賽道參數 `s` 沿中心線距離、`d` 橫向（正＝左）。
